# zodify v0.8.0 candidate

Unreleased. Publish only after local verification and an authorized package upload.

This candidate preserves deterministic `.env` parsing, adds canonical diagnostic
records without changing legacy issues, and introduces strict JSON object parsing
and conservative exact JSON Schema export. Numeric types/default insertion in the
unshipped exporter now raise UnsupportedSchemaError instead of silently losing
semantics. Trusted default references and dictionary-depth behavior are preserved.

The public website continues to document the verified 0.6.0 wheel until the
candidate is actually published and installed examples pass against that release.
Validation evidence belongs in the reviewed PR; no old test counts are release proof.

## Diagnostics cost

Structured validation preserves immutable canonical diagnostics alongside legacy
errors. In versioned Python 3.12 flat and nested synthetic fixtures, this increased
structured-mode successful-call time by 36–43% and failed-call time by 61–64%
compared with the verified 0.6.0 wheel. Default text-mode successful validation was
approximately unchanged; text-mode failures increased 9–11%. Import median rose
from about 2.3 ms to 4.3 ms. These measurements compare complete versions on one
machine and do not predict application-level performance.

Typed locations require traversal work even on successful structured calls;
failures also construct canonical messages and records while retaining the legacy
projection. This is an explicit diagnostic capability cost, not a speedup claim.
The release decision must acknowledge the tradeoff. No compiler is included.
