## Class schemas on Python 3.14

Python 3.14 defers class annotations. In 0.8.0, ordinary annotated `Schema`
subclasses can compile into empty schemas: missing required fields pass validation,
while valid input is rejected as unknown keys. This patch uses the standard-library
annotation API to discover fields during class construction.

Annotation expressions are evaluated once at class definition. Unresolved names
and unsupported string or postponed annotations fail at definition time. Direct
subclass restrictions, defaults, nested schemas, unions, and the single validation
engine remain unchanged. There are no new public APIs or required runtime
dependencies.

## Compatibility and verification

The declared support range remains Python 3.10–3.13. Fresh installs from PyPI
passed installed-contract checks, seven maintained package examples, and eleven
public documentation examples on macOS CPython 3.10.19 and 3.14.6. The checks cover
the published 0.8.1 wheel, including required-field rejection for class schemas;
the downloaded source distribution also matched its retained hash. These exact
checks do not establish a broader Python 3.14 support matrix. The earlier 0.8.0
artifacts do not contain this fix. Broader operating-system, free-threaded, or JIT
support is not claimed.

The diagnostics cost measurements and limitations in the
[0.8.0 release notes](https://github.com/junyoung2015/zodify/blob/main/release-notes/v0.8.0.md#diagnostics-cost) remain historical evidence. This
patch adds no diagnostics or compiler features and makes no new performance claim.
